# 正式协议 v1 与成员 B 交接

## 本步确定的范围

第四步 Baseline GPU 预检已通过，用户已批准 A 先运行全量 Baseline 的种子 13。正式设置固定到 `configs/training_protocol_v1.json`，运行参数在 `configs/baseline_seed13.json`。

第四步的 `configs/training_protocol.json` 和源码清单保持不变，作为历史预检证据；其中“等待双方预检”的状态文字属于第四步方案阶段。第五步按用户确认先执行 A 的全量实验，B 后续使用相同配置完成双前向预检。如果共同配置确需调整，A/B 都应使用新版本重跑，不能混用协议不同的结果。

v1 的模型、输入、损失定义、优化器、学习率调度、batch、精度、种子列表均沿用第四步确定的数值。变化是进入全量运行，并明确正式计时和日志口径。协议中的三个种子仍为 13、21、42；当前入口仅开放种子 13。

## 复用入口

- `src/baseline_model.py`：A 的普通单前向适配，保持第四步验收版本。
- `src/training_core.py`：优化器、调度、加权梯度累积、评价和前向计数，保持第四步验收版本。
- `src/experiment_runner.py`：新增共用的完整训练、最终 dev 评价、模型保存/重新加载、逐步日志和成本汇总。
- `scripts/baseline_formal_runtime.py`：只构建 Baseline，验证完整资源和种子 13 初始化；不是 B 的 R-Drop 入口。
- `scripts/run_step5.py`：环境/文件校验、项目锁、实时日志、失败反馈。

B 应基于作者固定 `bert_kl` 实现适配，保留来源与 patch，按第四步损失约定使用平均 CE 和按样本平均的对称 KL，α=0/0.5/1。第四步指出的原始代码系数与 reduction 差异仍适用，不能仅改源码中乘在 CE 上的局部 alpha。

B 可复用 `run_experiment()`，在自己的运行配置中设 `forwards_per_training_microbatch=2`，并提供训练时双前向、评价时单前向的模型适配。评价依旧使用完整 dev、FP32、最后一步 checkpoint。B 的入口需记录自己的算法源码、协议和运行代码哈希；不要修改 A 已归档的 Baseline 实现后仍沿用旧哈希。

## 训练计数

固定预算为 2,296 个 optimizer step，warmup 137；首个 warmup step LR=0，按已记录约定计入优化器调用。共有 2,287 个 16 样本更新和 9 个 4 样本尾批更新，总样本访问次数 36,628，microbatch 数 4,583；不同训练样本 ID 为 3,668。

Baseline 预期训练编码器前向 4,583 次、编码器样本处理 36,628 次；R-Drop 预期前向 9,166 次、样本处理 73,256 次。实际计数通过 hook 核对。重复前向不会增加独立输入样本数，这些计数也不等于精确 FLOPs。

每次运行记录相同输入清单、初始化参数哈希和训练顺序哈希，以供同种子的 A/B 比较。数据使用各 epoch 独立 RNG 洗牌，模型 Dropout RNG 不被采样计划消耗。

## 正式成本口径

主要耗时为 `training.train_loop_wall_seconds`：CUDA 同步后的完整训练循环墙钟时间，包含取批/拷贝、前向/反向、检查、梯度裁剪、AMP、优化器/调度、计数、逐步日志及每 100 步进度输出。不扣除首步启动开销。该时间是**带统一检查和日志的实现耗时**，不是纯 CUDA kernel 时间。

次要耗时 `sum_update_body_seconds` 是各更新内部计时之和，排除外层日志和部分循环处理；不能将它与另一条件的完整循环时间混比。两种时间均保留，平均每步时间分别注明分母和范围。

分词与模型加载在训练计时前完成，最终 dev 评价、模型保存/状态哈希和重新加载另行记录。训练前重置 CUDA 显存峰值，在评价前读取 allocated/reserved 字节数。它们不是整张显卡的 nvidia-smi 使用量。

A/B 在同一张 RTX 3090 上依次运行，并复用同一训练核心、进度间隔和计时逻辑。新入口使用 `runs/gpu_training.lock` 的 Linux 文件锁；B 的训练入口也应使用同一锁。文件存在本身不表示仍有任务，运行退出会释放内核锁。

报告记录 GPU/驱动/包版本及训练前后 nvidia-smi 快照，便于复核；快照不能保证整个训练期间没有其他外部任务，需要实际安排独占运行。额外开销以两种方法的同口径实测为准，不能直接假定精确翻倍或声称免费提高。

## 模型与结果交接

每次 `checkpoint-final` 含最终模型、config 和 tokenizer；只保存推理所需状态，不支持从该文件夹断点续训。正式每个种子都从固定原始预训练权重开始，失败运行不自动接着重试或覆盖日志。

`result.json` 用于后续汇总，`formal_report.json` 和逐条日志用于证据追踪。当前只产生种子 13，不能提前报告种子标准差；之后所有三种子完成时保留每个种子结果，汇总均值和样本标准差（ddof=1）。

最后一步 checkpoint 选择规则已固定，不按首个种子的 dev 分数调参或改选最好 epoch。若以后确需更改协议，应明确新实验版本并重跑所有对应条件。
