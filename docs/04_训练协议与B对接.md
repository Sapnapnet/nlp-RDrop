## 尾批与样本顺序

`src/training_core.py` 的 `make_update_plan()` 使用独立 `random.Random(seed + epoch)` 洗牌，不消耗模型 Dropout 的随机数。每个 epoch 保留所有样本，末尾不足两个 microbatch 时立即更新，不跨 epoch 拼接或丢弃样本。

完整 MRPC 一个 epoch 有 229 个 16 样本更新和 1 个 4 样本更新。每个 microbatch 的平均损失乘以 `该批样本数 / 本次更新总样本数` 后再反向。不能简单地始终除以 2，否则尾批梯度会减半。

对固定 2296 step 的正式计划，计数为 36,628 次独立输入样本访问、4,583 个 microbatch；这里“访问”包括不同 epoch 重复遇到的样本，不表示 36,628 条不同数据。Baseline 对应 4,583 次训练编码器前向；R-Drop 在无额外调用时对应 9,166 次。B 应用实际 hook 计数验证，不只写理论倍数。

相同种子下，A/B 需匹配输入清单哈希、初始模型状态哈希和 `batch_plan_sha256`。不要为了额外检查先消耗 Dropout RNG；本次 Dropout 探针执行后恢复 CPU/CUDA RNG 状态。

## 损失口径：A 确定，B 按作者实现适配

Baseline 使用作者已有的单前向 `bert_cross_entropy`，其 CE 对样本取平均。

为维持 CE 尺度并使 α 不随 microbatch 大小变化，共同约定 R-Drop 为：

```text
CE = 0.5 * (mean(CE1) + mean(CE2))
SKL = 0.5 * mean_over_examples(sum_over_classes(KL(P1 || P2) + KL(P2 || P1)))
loss = CE + alpha * SKL
```

这里两个方向的 KL 均先沿类别求和，再沿样本平均；用 FP32 的 log_softmax/softmax 计算，两组分布都保留梯度，不 detach。α 固定取 `0,0.5,1`。

这与分工文档的 CE 相加形式、作者 `bert_kl()` 的 CE 相加/KL 总和形式存在归一化差异，需要在报告中明确写出。CE 平均形式与作者仓库 README 示例一致，KL 另明确为 batch mean。不能把本项目的 α 数字直接等同于作者脚本内硬编码系数；例如作者现有总损失整体除以 2 后，其 KL 项相当于本约定 α=`0.25 × microbatch样本数`，会随尾批大小改变。

α=0 仍保留两次随机前向及平均 CE，不要求与单前向 Baseline 的轨迹相等。系数消融各条件只改变 α，其他设置保持一致。

**B 必须基于固定作者 `bert_kl` 做上述适配并保留修改差异**，尤其要区分源码中乘在 CE 上的局部 `alpha` 与真正的 KL 系数。第四步没有修改该算法或替 B 实现 R-Drop。正式评价统一关闭 Dropout，走单前向，不能沿用作者默认的双前向评价入口。

## 代码接口

- `src/baseline_model.py`：继承作者模型，仅将 forward 路由到作者已有 CE 方法；保存和加载都显式使用 `BaselineBertForSequenceClassification`。直接使用作者默认类重新加载会回到双前向路径。
- `src/training_core.py`：共用采样计划、按样本加权的梯度累积、优化器、调度、指标、模型哈希和前向计数。
- `train_update()` 要求模型返回该 microbatch 的**平均损失**；B 接入时 `expected_forwards=2`，并自行实现由 train/eval 状态决定的前向适配。
- `evaluate()` 按样本累计平均 loss；计算 Accuracy、正类为 1 的 binary F1，分母为零时返回 0。本次与 scikit-learn 交叉检查。
- `scripts/baseline_smoke_runtime.py`：阶段入口，包含资源验证、Dropout 探针、20 步训练、评价和 checkpoint 推理加载验收。

本次源码算法文件 SHA256 保持 `1316e7d6990cd9a12f08689dbb3cf0fcd5b165bcc981e519f46babe5f66cbf06`。B 后续修改时须另记录新源码哈希和 patch，不可仍把修改后的源码说成与作者字节一致。

## 日志与成本口径

逐步日志保留 `update/epoch/native_ids/loss_mean/grad_norm_before_clip/lr_used/amp_scale/optimizer_step_calls/examples_seen/microbatches/encoder_forward_calls`，诊断计时另列。保存原始种子结果，正式汇总同时给出每种子的 Accuracy/F1、均值和样本标准差（ddof=1）。

汇总区分：

- optimizer.step 实际调用数；首个 warmup LR=0 的调用也按调度约定计一步。
- 输入样本访问次数与不同 ID 数量。
- 编码器前向次数、编码器处理样本次数、含 padding 的 token 位置处理次数。
- 训练循环耗时、各更新耗时、评价耗时、模型保存/加载耗时。
- 训练阶段 CUDA 峰值 allocated 和 reserved 显存（不等于整张卡 nvidia-smi 使用量）。

前向次数与样本处理次数是计算工作量指标，不是精确 FLOPs。正式计时须在同一张 GPU 上依次运行，各条件采用相同检查和计时范围，并明确包含哪些开销；不能用第四步带诊断检查的小样本耗时作正式成本结论，也不能声称双前向免费提高性能。
